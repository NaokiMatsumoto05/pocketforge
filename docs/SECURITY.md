# セキュリティと公開条件

これは公開前の開発版です。以下は実装済みの保護と、未検証・未実装の境界です。

## 実装済み

- ユーザー・プロジェクト所有権の検証を全操作に適用。
- scryptによるパスワードハッシュ、ランダムセッション、期限・ログアウト失効。
- WebはHttpOnly / SameSite cookie。本番モードはSecure cookie。
- ネイティブのセッションはSecureStore。接続先はHTTPSのみ。
- Origin検証、CORS許可リスト、リクエストサイズ・認証試行の制限。
- サーバー保管キーはユーザー別にAES-256-GCMで暗号化。プロジェクトに注入しない。
- パスの絶対指定・親参照・.git・.env等を拒否。サイズ・数・履歴容量を制限。
- revisionで競合を検出。AI/実行ジョブ中は同じプロジェクトへの書き込みを拒否。
- APIホストでユーザーコードを実行しない。コマンドはE2B内のみ。
- E2Bは外向き許可リストと公開ポート認証を要求。キーをクライアントへ返さない。
- ZIP取得は認証済みユーザーが発行した一回限り・60秒期限のリンク。
- 本番設定はHTTPS originと明示的なマスターキーを必須化。登録は本番で既定停止。

## 公開前に必要

- 実E2Bのテナント分離・ネットワーク・プロセス停止・CPU/メモリ/ディスク上限の検証。
- 任意コードの出力・エラー・巨大ファイル・悪意ある依存関係を使った負荷試験。
- イベント/ジョブ全体の容量管理、ユーザー総数制限、キュー・分散ロック。
- アカウント復旧・パスワード変更・メール確認・運用管理画面。
- マスターキーの外部管理・ローテーション、バックアップ・復元演習。
- EASトークンはユーザー本人のものだけを使う。自分のアプリ設定コードが自分のトークンへアクセスし得ることを含め、ビルド資格情報の権限を検証。
- ログに既知のキーが出た場合は伏せ字化するが、任意の秘密を完全検出するDLPではない。
- スキーマプレビューに任意HTMLを渡さない。実行プレビューには別オリジンの認証済みプロキシが必要。

## 依存関係

2026-10-25のnpm auditで、Expo CLI依存系列にHigh判定が5件残っています。
対象はExpo / @expo/cli / @expo/code-signing-certificates / node-forge / CLI内Zodです。

APIの静的ファイル配信は修正版@fastify/static 10.1.7へ更新しました。
Expo系の警告は互換性を確認せず別メジャーへ強制更新していません。
node-forgeは確認時の最新版1.4.0にも警告があり、Expo CLIのZod 3系から4系への無検証overrideは行いません。

これらは主に開発・署名ツールチェーンの依存で、APIはExpo CLIを要求ハンドラから実行しません。
ただし安全性を保証するものではありません。公開・署名運用前に公式修正版の確認と再監査が必要です。
